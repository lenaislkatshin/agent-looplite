# 与 Pi TS 原版的行为对照

把同一份录制的 SSE 分片回放给 Pi TS 原版和本库，逐条比对。脚本在 `scripts/pi_parity/`。

## 方法

- 分片来自一次真实网关探测：Chat Completions 流式，思考关，模型先说一句话，再在同一条回复里调用两次 `lookup_rule`。共 15 个分片，两个工具调用的参数各分 5 片，第一片里参数为空字符串，最后两片是结束原因和用量。分片不放进仓库。
- 本地服务按路径区分调用方：第 1 次请求回放这 15 个分片，第 2 次请求回一段固定的回答。两边收到的字节完全相同。
- 两边都用上层 `Agent`，系统提示词、工具、问题相同，工具按文号返回固定文字。事件写成同一种格式，角色名和结束原因按 Pi 的写法。
- Pi 一侧是 `@earendil-works/pi-agent-core` 和 `@earendil-works/pi-ai` 1.5.2，用 `openAICompletionsApi()` 接本地服务。

```bash
scripts/pi_parity/run.sh <分片文件>
```

分片文件是 JSON 数组，每个元素是一个 `data:` 后面的分片对象。

脚本比较双方的请求编号，再逐项比较相同编号的请求体。请求编号、事件、工具执行或消息有差异，或请求体在约定之外有差异时，脚本打印差异并以退出码 1 结束。约定差异是 Pi 多发的 `max_completion_tokens`、`store` 和用户消息的内容块格式，比对前先去掉。

## 结果

2026-11-12，提交 `4a01704` 之后的连接器。

| 比对项 | 结果 |
|---|---|
| 事件序列 | 两边各 43 个，逐条一致，包括每个增量的类型、块序号、内容，工具调用的 ID 和名字 |
| 工具执行 | 一致，顺序为甬交规〔2026〕7号、9号 |
| 消息 | 5 条一致：角色、正文、工具调用的 ID 和参数、结束原因、用量、错误标记 |
| 请求体 | 有三处不同，都是有意的差异，见 `docs/design.md`“与 Pi 的差异”中的“Chat Completions 请求体”：用户消息的格式、`max_completion_tokens`、`store` |

修正前的同一组比对有两处事件差异，已按 Pi 改正：工具调用开始时提前结束了正文块；参数为空字符串的分片没有发 `toolcall_delta`。

只覆盖了这一种响应：流式、思考关、一条回复里两个工具调用。思考开、整轮返回、出错和取消还没有用录制的分片对照过。
